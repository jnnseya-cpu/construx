# CONSTRUX end-to-end audit — October 2026

A whole-platform review and test, from the chair of a **real client who has no
access to the AI assistant** — the lens being "can an unaided user actually
complete what the product invites them to do, without a dead-end, a fake
figure, or an error they can't act on."

Scope: ~100 domain modules, 14 engines, ~60 frontend pages, 1,277 routes. Two
passes: **Pass A** drove the real HTTP gateway in-process as a logged-in user;
**Pass B** ran deep per-area code+UX reviews, each tracing capabilities end to
end (frontend → route → domain → ledger → UI) and reporting only verified,
evidence-backed findings.

Severity: **P0** platform/money failure · **P1** critical feature unusable ·
**P2** functional defect · **P3** improvement · **P4** cosmetic.

> **Remediation status (updated as work lands).** The systemic P1 — the missing
> write-UI across stage workflows — has now been **closed for the reviewed
> workflows**, each with a gateway journey test that drives the exact payloads
> the buttons send and asserts the flow completes: submittals, design
> change/baseline, concept stage (gate opens), construction progress +
> deliveries + commissioning dossier, handover acceptance spine, meeting-action
> close, and project-invitation accept/decline. Security/correctness/honesty
> fixes from the audit are also applied (see "Fixes applied"). The frontend
> quick-wins are now applied too: economy "0 ACU" field map, account
> blank-on-error, permissions label drift, portfolio "AM" region, estate
> module-gate heading, billing "Issue invoice" relabel, commercial double-dialog,
> the duplicate procurement clarification command key, and the field.js
> site-capture dead-end. Still open: the handover **requirements-matrix**
> sub-workflow (being built); two backend P2s (award-departures-blind,
> conditional handover acceptance never lapses); and the autopilot **§16.1
> disclosure on "Approve and run"** (charge integrity is already correct — this
> adds the transmission disclosure and needs the proposal→command→quote wiring,
> so it is a focused follow-up, not a quick-win).

## Pass A — real-user HTTP sweeps (executed, not read)

Booted `createGateway(platform)` in-process, seeded a tenant, logged in as the
enterprise owner, and exercised the real pipeline (validation → authz →
problem+json).

- **Read surface (275 GET screens reached): 0 broken (5xx), 0 fake-data hits.**
  Every parameterless/project screen a logged-in user can open renders. No
  white-screen-of-death.
- **Write surface (463 POST/PUT hit with an empty body): 0 crashes (5xx).** A
  fumbled/empty form returns a clean, actionable `400 VALIDATION_FAILED`
  (problem+json), never a 500. Verified in isolation on representative tenant
  writes (`/v1/projects`, daily-logs).
- **Refusals are clean and actionable.** The owner's 68 read denials are the
  correct tenant-vs-operator boundary (`PLATFORM_ADMIN_REQUIRED` for `/v1/admin/*`,
  `MODULE_NOT_GRANTED` for `/v1/bid-on/*`) — well-worded problem+json, not walls.
- **`/v1/documents/lifecycle/:projectId` 404** was a sweep param mismatch, not a
  dead-end: the route is `:id` = *document* id, tenant-scoped; the frontend only
  ever calls it with a real document id. Cleared.
- The apparent "453 writes → 401" in the bulk write-sweep was **self-inflicted**:
  the loop hit `POST /v1/auth/logout` partway through, which revoked the session
  token, so every later call 401'd (`"Token has been revoked"`). Not a defect.

**Pass A verdict: the platform's HTTP surface is robust — it loads, it validates,
it refuses cleanly, and it does not crash or show fake numbers on reads.** What
Pass A cannot see is whether a *multi-step journey completes* — that is Pass B.

## Pass B — deep per-area reviews

Twelve areas, one reviewer each. **All 12 complete.** Each traced its
capabilities end to end and reported only verified, evidence-backed findings.

### Systemic pattern (the headline)

Across the two areas reviewed so far that are *stage workflows* (Concept and
Design), the same defect recurs and it is the one that matters most to an
unaided client: **the backend is complete and the screen is a rich read
surface, but the write commands that move the stage forward were never wired
into the UI.** The client can see everything and complete almost nothing past
"create". This is the Bid-On pattern (read-complete, write-affordances-missing)
at platform scale, and it is the primary thing standing between CONSTRUX and
"a client can use it without the assistant."

### Area 1 — Money / billing / commercial / valuation

Backend money engine traced end to end (reserve→settle→release, floor/multiplier,
top-up→receipt→credit, subscription settle + allowance, FX, refund/dispute,
group allocation, seat/invoice issuance). **No money-correctness, double-bill,
authz or tenant-isolation defect found — the commercial core is solid.** Defects
are presentation-layer:

- **[P3] `frontend/pages/economy.js:218-223`** — operator "What is sold" price
  list shows every ACU bundle with a blank name and **"0" ACU**. It reads
  `bundle.label/id/units`, but `/v1/billing/catalogue` returns objects keyed
  `{bundle, priceMinor, multiplier, usableAcus, providerCostMinor}` — so name is
  blank and the ACU column is a hardcoded-looking `0` on a panel captioned "the
  published price list". A figure not derived from real state (rule 9). Fix: read
  `bundle.bundle` and `bundle.usableAcus`. **[verified]**
- **[P3] `frontend/pages/commercial.js` (CVR/EVM handlers)** — after publishing a
  CVR or taking an EVM snapshot, the handler re-enters via `commercial(root)` on
  the same `#view` element instead of `draw()`, re-binding the delegated
  listeners; the next command opens **two** stacked dialogs. Fix: call `draw()`.
- **[P4] `frontend/pages/billing.js`** — "Issue invoice" button actually does a
  read-only statement preview (real issuance is operator-only). Relabel to
  "View statement".

### Area 2 — Golden Thread ledger / audit / events / documents

Ledger integrity, tenant isolation and audit-screen honesty traced and **found
genuinely solid** — no write breaks the hash chain, bypasses append-only, writes
outside the closed catalogue, or records governance as AI-authored; the
"verified/intact/journal agrees" labels come from real checks.

- **[P2] `backend/src/domain/informationcontrol.ts:497-507`** — a *withdrawn*
  verbal direction emits `eventType: 'DIRECTION_CONFIRMED'` (there is no
  `DIRECTION_WITHDRAWN` in the catalogue). The replay narrator builds its text
  from the event type, so the Golden Thread timeline narrates **"direction
  confirmed"** for a withdrawal — the opposite of what happened. An honesty
  defect in the audit record itself. Fix: add a `DIRECTION_WITHDRAWN` catalogue
  code (UPDATE, UnconfirmedDirection, CONTRACTS_CLAIMS, aiAllowed:false) and emit
  it. **[verified pattern]**
- **[P3 / likely settled] `backend/src/domain/correspondence.ts:471-549`** — a
  quotation/CE is reported `deemedAccepted` the instant the reply period lapses,
  with no model of NEC's "notify the failure to reply" step. STATE.md documents
  the simplified behaviour as intended, so flagged for a product/legal decision,
  not asserted as a bug.

### Area 3 — Concept / design  ⚠ **the critical area**

Backend complete (52 concept routes, all write paths `authorise()`-guarded, gate
refusals honest). But the write surface is missing from the UI:

- **[P1] The entire Concept stage is uncompletable through the UI.** The command
  bar (`frontend/pages/concept.js:80-124`) offers 7 create commands; ~17 further
  write routes (analyse/select/reject option, create cost-plan, cost-plan,
  programme, cashflow, controls/approve, the three strategies, compliance screen,
  risk review, due-diligence, constraint assess, authority matrix, brief/baseline)
  have **zero frontend affordance**. `approveConceptBaseline` refuses with
  `GATE_NOT_MET` until those exist, so "Freeze concept baseline" is a permanent
  dead-end. **[verified — grep finds no frontend reference]**
- **[P1] "Add cost line" dead-ends:** it needs a cost plan, but the only route
  that creates one (`POST .../concept/cost-plan`) has no UI. First click fails
  with `NO_COST_PLAN` and no way forward. **[verified]**
- **[P1] The design-change journey is entirely absent from the UI**
  (`design.js:899-913` is a read-only register; no propose/assess/decide/
  implement/close command). A designer cannot raise or approve a change to
  approved design. **[verified]**
- **[P1] Design baselining is absent:** no freeze-package, approve-baseline or
  MIDP command. A package can never be frozen or a baseline approved through the
  product, so the 7.4 design gate can never be met by a user. **[verified]**
- **[P3] Options panel shows "No option has been analysed" with no action** to
  analyse/select (symptom of the P1 above).

Root cause: the Concept/Design screens were built as rich read surfaces over
complete backends; the write commands were never added to the command bars. A
half-built vertical (rule 8) presented as finished (rule 9). STATE.md does not
disclose these as gaps.

### Area 4 — Identity / auth / tenancy / onboarding

Core auth hardening (tokens, MFA, lockout, decoy-for-unknown, role-escalation
guards, `projectContext` isolation, signup→verify→sign-in) traced and **solid**.

- **[P1] No UI anywhere accepts a project invitation.** Invite works and emails
  the invitee "sign in once accepted", but the accept route
  (`POST .../invitations/:id/accept`) is **called by no frontend file** (only
  *withdraw* is); the invitee has no identity so cannot log in to accept either.
  The invitation sits PENDING, holds a Controller seat for 14 days, then lapses.
  A surfaced feature that can never complete. (The admin "Add a person" path is a
  working alternative, which is likely why this went unnoticed.) **[verified]**
- **[P3] `acceptInvitation`/`declineInvitation` perform no `authorise()` check** —
  a weaker door than the admin-gated user-creation path; acceptance is what
  actually mints an identity. Today API-only (no UI). Fix: gate with
  `PROJECT_SETUP:R` + `worksOnProject`.
- **[P3] `frontend/pages/account.js:26`** — the `/v1/me/erasure` fetch has no
  `.catch`; any failure blanks the whole Account page (which hosts account
  deletion), unlike every sibling screen. Fix: the standard `.catch`+refusal.
- **[P4] `frontend/pages/permissions.js:45-54`** — a local `CODE_LABEL` map
  disagrees with the server's (`I`=Issue vs Import/export, `X`=Execute vs Run AI,
  a non-existent `D`), on the very screen meant to explain refusals. Fix: render
  from the matrix response's published meanings.

### Area 5 — Procurement / tender pipeline (excl. Bid-On)

Pipeline traced (intake → analysis → ITT/enquiry → quotation → award →
framework). Deterministic bid scoring, award-departure machinery, waivers,

- **[P1-security → fixed as P2] `backend/src/domain/tenderintel.ts` `requireComparison`** — a

- **[P2] `backend/src/domain/award.ts:406-419`** — award "departure" detection
  compares awarded terms to `pack.state.submittedTerms`, but **nothing ever
  writes `submittedTerms`**, so every date/LD/cap/retention change is reported as
  *no departure* and `convertAward` bakes the changed terms into the budget
  undetected. The exact loss the module exists to prevent. Fix: capture the bid's
  commercial terms at compile/submit. **[verified; not yet fixed — larger]**
- **[P2] `frontend/pages/procurement.js`** — the `COMMANDS` key `clarification`
  is defined twice (RFQ-TQ and tender-clarification); the later wins, so the

- **[P3] `backend/src/domain/procurement.ts` `reconcileTenderResponses`** — RFQ

## The headline: one systemic defect, many instances

The single most important finding, repeated in **every stage-workflow area**
(concept, design, submittals, construction progress + delivery, commissioning,
handover, completion, aftercare, meetings, invitations): **the backends are
complete and the screens are rich read surfaces, but the write commands that
move a workflow forward were never wired into the UI.** A client can watch state
and create initial records, but cannot drive a project to completion — the stage
freezes, the register only grows, the "next command" is printed with no button.

This is the Bid-On pattern (read-complete, write-affordances-missing) at platform
scale, and it is the thing standing between CONSTRUX and "a client can use it
without the assistant." It is not a backend defect and not a security defect —
it is an **unfinished UI vertical presented as finished** (rule 8 / rule 9), and
it is largely **not disclosed in STATE.md's "what is not built"**.

The affected write journeys, each needing command specs + panel affordances wired
the way Bid-On's and `design.js`'s existing commands are:

| Area | Missing write journey |
|---|---|
| Concept | analyse/select option, create cost-plan, programme, cashflow, approve controls, 3 strategies, compliance screen, risk review, due-diligence, brief baseline, freeze concept baseline |
| Design | raise→**submit** submittal, resubmit, record-ordered; raise/assess/decide/implement/close design-change; freeze package; approve baseline; MIDP |
| Construction | set measurement-basis / submit progress-claim / verify; goods-in book/receive/accept/install |
| Commissioning | compile dossier; complete commissioning |
| Handover | compile pack, decide, activate operations, baseline, transfer residuals, requirements matrix |
| Completion | release turnover, accept construction completion, practical-completion inspection/certificate |
| Aftercare | start, seasonal commissioning, feedback; operator-readiness acceptance; regulatory pack approve/submit |
| Meetings | close action; record correction |
| Onboarding | **accept/decline a project invitation** |

## Fixes applied in this audit

Verified, typechecked, and covered by the full suite (7,800+ tests) plus the
noted targeted tests. Each mirrors a pattern already tested elsewhere in the
codebase.

- **Bid-On customer-guest dead-end (P1)** — classified the two bootstrap reads
  `guest: 'OWN'` so the external guest's screen loads (`routes.ts`).
- **Competitor-pricing cross-project leak (P2/security)** — `tenderintel.ts`
  `requireComparison` now scopes by tenant + project.
- **RFQ-reconcile cross-project leak (P3)** — `procurement.ts` scopes the RFQ.
- **Site-model cross-project read (P3)** — `sitemodel.ts` `requireModel` scopes by
  project, matching `heldIfc`.
- **Structural parent-scope gaps (P3)** — `structure.ts` validates `createPortfolio`'s
  enterprise and tenant-checks `createProject`/`createProgramme`'s parent portfolio.
- **Audit-timeline honesty (P2)** — a withdrawn direction now emits a new
  `DIRECTION_WITHDRAWN` event type instead of `DIRECTION_CONFIRMED`, so the Golden
  Thread no longer narrates "confirmed" for a withdrawal (`eventTypes.ts`,
  `informationcontrol.ts`; catalogue test added).

### Not yet fixed (recorded for decision / next batch)

- **Award departures blind (P2)** — needs the bid's commercial terms captured at
  compile/submit before `departuresBetween` can see a moved date or doubled LDs.
- **Conditional handover acceptance never lapses (P2)** — derive lapse on read and
  refuse activate/baseline past an unmet `expiresOn`.
- **The systemic write-UI gap (P1, large)** — the table above. This is a multi-screen
  build mirroring the Bid-On effort per stage; recommended to be done stage by
  stage, highest-traffic first, and disclosed in STATE.md as it lands.
- The frontend quick-wins (economy "0 ACU", account blank-on-error, permissions
  label drift, portfolio "AM", procurement duplicate command key, field.js capture
  guard, estate.js module-gate label, commercial.js double-dialog, billing.js
  label, autopilot §16.1 disclosure) — each small and clearly-correct.
