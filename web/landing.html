The structural failure

Construction manages what already happened.

It is not short of tools. It is short of a record complete enough to forecast from. Estimates are static, so risk is guessed. Programmes carry no probability, so delay is discovered. Evidence is scattered across inboxes, so entitlement becomes an argument.

Conventional stack

  • ✕ Documents in folders, versioned by filename
  • ✕ Monthly reports assembled by hand
  • ✕ Dates edited directly in the programme
  • ✕ Risk buried inside a percentage
  • ✕ Claims reconstructed after the fact
  • ✕ Data dies at handover

CONSTRUX

  • ✓ Immutable events, chained and verifiable
  • ✓ Forecast final cost recomputed as reality moves
  • ✓ Dates are an output of the network, never an input
  • ✓ Risk priced as an explicit line with a P80 figure
  • ✓ Entitlement computed continuously from the record
  • ✓ The same spine runs the asset for thirty years
The Golden Thread

Evidence you can hand to an adjudicator and let them check.

Nothing writes state directly. Every change is an event carrying the hash before, the hash after, and a chain hash over its predecessor. Remove one event and every hash after it breaks — which the replay engine reports at the exact point of the break.

POST /v1/projects/:id/audit/replay 
{
  "eventsReplayed": 217,
  "verificationStatus": "VERIFIED",
  "rootHash": "sha256:109369e88ebd3d38cff9…",
  "summary": { "VERIFIED": 217, "FAILED_HASH": 0 },
  "baselinesInForce": {
    "programmeBaselineId": "01M00T…",
    "budgetBaselineId":    "01M00T…"
  }
}

// after altering one stored hash directly in the database
  "verificationStatus": "FAILED",
  "failures": [{ "status": "FAILED_HASH",
              "eventType": "ESTIMATE_FROZEN" }]
  • 1
    Append-only, enforcedNo destructive update exists. State changes only by committing an event, and the event and the state land together or not at all.
  • 2
    Canonical hashingKeys sorted, whitespace stripped, audit metadata excluded, array order preserved. Two parties holding the same record compute the same hash.
  • 3
    Constrained patchesAdd, remove and replace only, in a mandated order. Ambiguous operations are rejected because a replay must be reproducible.
  • 4
    Evidence enforced at commitEvents that require evidence cannot be written without it. Progress without a photo is not progress.
  • 5
    One attestation valueA single project state root that any party holding the log can recompute — for an insurer, a regulator or a tribunal.
Seven engines, one spine

The maths is arithmetic. The judgement is labelled.

Critical paths, earned value, bid scores, contingency and delay attribution are computed — reproducible by hand, identical on every run. Models contribute classification and narrative, and never write state on their own.

ENGINE A

Tender & Commercial

Take-off to award as a state machine: measurement, schedule, route split, package, returns, adjudication, locked bid pack.

Computes: deterministic bid scoring, variance detection, cost build-up
ENGINE B

Planning & Delivery

The programme is recalculated from the activity network every time. Dates are never edited, so "what changed and why" is always answerable.

Computes: CPM forward/backward pass, float, PERT P80 duration
ENGINE C

Resource & Cost

Budget, commitments, actuals, accruals and progress on one spine, so forecast final cost moves the moment reality does.

Computes: earned value, live CVR, S-curve cashflow, notice dates
ENGINE D

Risk, Safety & Compliance

Risk quantified in money and days. Safety predicted from leading indicators, so controls land before an incident rather than after one.

Computes: expected value, P80 contingency, safety risk index
ENGINE E

BIM & Digital Twin

Drawing control with enforced supersession, clash triage weighted by rework cost, and a twin fed by what the site actually looks like.

Computes: revision supersession, clash severity, as-built reconciliation
ENGINE F

Contracts, Change & Claims

Change as a chain: origin, notice, impact, instruction, valuation and downstream effect — each link timestamped and hashed.

Computes: delay attribution with concurrency, entitlement scoring
ENGINE G

Handover & O&M

Where most construction data dies. Here the asset register in year twelve still resolves to the drawing revision it was built to.

Computes: handover completeness, reliability-adjusted maintenance forecast
COPILOT

Grounded, not chatty

Answers from project state and says the record is empty rather than answering from general construction knowledge. Proposes commands; never executes them for you.

Enforces: role-scoped tools at the current lifecycle phase
DUAL BRAIN

Perception sees. Reasoning decides.

Drawings, models and site imagery to a perception model; contracts, liability and commercial logic to a reasoning model. Both behind adapters, so neither is a dependency.

Enforces: structured output only — prose never becomes state
